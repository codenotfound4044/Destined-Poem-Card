# 世界书树状条目：地点扫描、关键词与顺序

命定的势力、城市、区位条目是一棵按地点展开的树：玩家走到哪里，哪一枝就亮起来，并在提示词里拼回一段有层级的 YAML。它靠三件事一起成立，缺一件就会出现"该亮的没亮"或"亮了但挂错了地方"。新增地点、拆分条目或调整顺序前先读本页。

## 一、三层机制

### 1. 当前地点进入扫描

变量 `世界.地点` 是一条从大到小的路径，格式定义在 `worldbook/命定之诗/变量/[mvu_update]变量更新规则.yaml` 的 `地点.format`：`大陆+方位-势力/区域-子级势力-聚落/地标-区位-详细位置`，保留 4~8 层。

变量本身不会被世界书扫描。自动化脚本在生成前把它作为扫描材料注入：

- `packages/automation/src/prompts/game-info.ts`：读取 `stat_data.世界.地点`，以 id `当前所在地点` 注入，`position: 'none'`（不发给模型）、`should_scan: true`（参与绿灯扫描）。同批还有 `主角种族`、`当前时间`。
- `packages/automation/src/runtime/start.ts`：在 `GENERATION_AFTER_COMMANDS`、`MESSAGE_SENT`、`MESSAGE_UPDATED` 时注入；读的是上一楼（`message_id: -2`）的变量，见 `runtime/host.ts`。
- `packages/automation/src/utils/index.ts` 的 `uninject()`：变量更新结束时清掉旧注入，避免旧地点残留。

所以整条路径里的每一段地名（例如 `诺斯加德-长夜之境-挽歌堡-黑冠台`）都会出现在扫描文本里，上下级条目可以在同一轮里各自命中，不需要开递归。

### 2. 关键词：本级名做主关键词，上级名做次关键词

| 层级 | 主关键词 | 次关键词（与任意） | 例子 |
| --- | --- | --- | --- |
| 势力 / 城市总述 | 本级名、别名、少量主题词 | 无，或上级范围名 | `雾晶港`：主 `雾晶港、雾海之珠、港口…`，无次关键词 |
| 区位 / 地块 | 本级名（可加主题词） | 直接上级名 | `黑冠台`：主 `黑冠台`，次 `挽歌堡` |
| 专题（政治、文化等） | 主题词 | 所属势力或城市名 | `雾晶港-政治与社会`：主 `政治、权力…`，次 `雾晶港` |

次关键词用 `与任意`（AND ANY）收范围：只有上级名也在扫描文本里时才亮，避免别的城市里聊到"港口""学院"时误亮。

`与任意` 不区分"当前地点"和"聊天历史里提过的地点"：最近几楼提到过的旧地名、本轮同时聊到的另一座城，都会让对应分支一起亮。这是关键词扫描的固有行为，测试时要专门覆盖。

### 3. 正文：YAML 片段按缩进拼成子树

势力区块被 `[本体][势力]➡️势力开始`（`<势力>`，顺序 31）和 `➡️势力结束`（`</势力>`，顺序 350）包住。区块内的条目正文是 YAML 片段，子条目不写父级键，而是靠缩进挂在前一条的结构下面：

```yaml
# 诺斯加德联盟-城镇-挽歌堡.yaml（顶层，缩进 0）
挽歌堡:
  地点类别: 大型城市(要塞)
  区位:
    行政: 黑冠堡（黑冠台）…

# 诺斯加德联盟-城镇-挽歌堡-黑冠台.yaml（缩进 4，接在 挽歌堡.区位 下）
    黑冠台: |
      峡谷西端最高处的岩质台地…
```

也有自成一段的写法：以 `---` 开头、顶层键自带完整名称（如伯伦斯法环的 `雾晶港:`、`汐潮学园区（雾晶学院）:`），不依赖前一条。`[分割线]` 条目只输出一行 `#地块名` 注释，用来给后面的城市分组。

缩进挂靠的条目，模型看到的是"按输出次序拼接后的文本"。所以子条目真正挂在哪个父级下，取决于酒馆的输出次序，而不是 `命定之诗.yaml` 里的书写次序或目录结构。

## 二、由此得出的硬规则

**名称一致。** 同一个地点在四处必须是同一个字：变量路径里的段、条目主关键词、上级正文里列出的名字、正文 YAML 键。模型只会写它在上下文里见过的地名，新区位要先出现在上级条目正文里（比如城市的 `区位` 列表），模型才会把它写进 `世界.地点`。如果地点也上地图或参与路线，`content/geography/places.yaml` 的 `name` 也用同一个名字，别名放 `keywords`。

**子条目亮，父条目必须也亮。** 缩进挂靠的子条目一旦在父条目缺席时单独出现，就会挂到前面随便哪个条目下面，变成归属错误的碎片。检查方法：子条目的次关键词里的每个词，单独出现时都要能点亮父条目（通常就是父条目的本级名）。专题类子条目（政治与社会、文化）也一样。

**地点树条目不设黏性。** 当前地点每次生成都会注入，人在哪里那一枝就每楼都亮，黏性只会让离开后的旧地点多留几楼、多占 token。子条目设了黏性而父条目没有时，离开后子条目还在、父条目先消失，就成了碎片；酒馆的黏性在生效期间也不会因再次命中重新计时，父子同值也可能差几楼结束。黏性、冷却留给随机事件这类需要"持续 N 楼、隔 N 楼再出"的条目（例如克苏鲁 DLC 的怪物生态），不挂在别的条目下面的独立专题需要时也可以用。

**父子同一插入位置。** 拼接只发生在同一个插入位置里，父在 `角色定义之前`、子在 `角色定义之后` 时不会挂到一起。

**顺序决定挂靠。** 酒馆把同一位置的已激活条目按 `顺序` 降序排好，再逐条 `unshift` 进提示词（`world-info.js` 的 `sortFn` 与 `WIBeforeEntries.unshift`），结果是顺序小的在前；同号时反而是清单里靠后（uid 大）的先输出，带黏性的条目还会被提前。所以：

- 缩进子块的顺序必须大于父块。
- 从父块的号到它最后一个子块的号，这个区间里不能有不属于这棵子树的条目，同号的也不行。反例：原来灰岩镇和琥珀加德都是 110、琥珀加德的区位是 111，同号倒序后输出变成"琥珀加德 → 灰岩镇 → 区位"，区位挂到了灰岩镇下面；龙吼堡垒、霜镜港、白港共用 113/114 时，龙吼堡垒的区位会挂到白港下面。
- 同一个父块下的兄弟可以同号（例如挽歌堡的五个区位都是 93），代价是它们会倒着输出；在意兄弟之间的先后就分开编号。

`pnpm card check` 会按这几条检查已启用条目，有问题时打印 `[挂靠]` 警告并在工作台首页列出，不阻止构建。它按清单次序和正文首行缩进推断父子关系，只看号段和黏性，不判断关键词能否点亮父条目。

## 三、顺序布局

命定条目多、DLC 和作者多，采用按区块留号段的布局，不做 1..N 连续重排。新条目插进所属区块的空号里；区块用完了再整体后移，不要侵入相邻区块。

| 插入位置 | 顺序段 | 内容 |
| --- | --- | --- |
| 角色定义之前 | -1 ~ 3 | 世界设定 |
| | 10 ~ 30 | 种族（本体与 DLC 种族多数同号 14，互不缩进挂靠） |
| | 31 / 350 | `<势力>` 开始 / 结束 |
| | 32 | 势力概览 |
| | 33 ~ 44 | 奥古斯提姆帝国（帝国专题 33~37，行省 38，城镇 39，城镇下属 40~41，红叶镇一组 42~44） |
| | 60 ~ 65 | 索伦蒂斯王国 |
| | 80 ~ 116 | 诺斯加德联盟（每座有区位的城市占两个号：城市、区位） |
| | 120 ~ 126 | 伯伦斯法环 |
| | 150 ~ 160 | 翼民圣国梵尼亚 |
| | 180 ~ 196 | 兽族联盟 |
| | 200 ~ 217 | 精灵王庭 |
| | 239 ~ 243 | 萨赫拉联邦 |
| | 270 ~ 280 | 瓦伦蒂亚 |
| | 338 ~ 339 | 永夜盟约 |
| | 351 ~ 400 | 组织 |
| | 401 ~ 500 | 冒险区域（每个区域一个十位段） |
| 角色定义之后 | 503 ~ 504 | 怪物生态 |
| | 550 ~ 590 | 产业 |
| | 600 ~ 700 | 角色（本体与 DLC 角色） |
| 指定深度 | 510 ~ 1102 | 额外设定（规则类，按深度与角色分组） |
| | 9999 ~ 99998 | 变量、MVU 规则、输出格式 |

表是写这页时的快照，以 `命定之诗.yaml` 为准；新增区块时顺手更新这张表。指定深度的条目先按 `深度` + `角色` 分组再比较顺序，和上面两个位置的拼接规则无关。

区块内按"总述 → 专题 → 地块 / 分割线 → 城市 → 城市的区位"排，城市和它的区位紧挨着，下一座城市接在上一座城市的全部区位之后。

## 四、新增一个地点

以"在挽歌堡下加一个区位"为例，加城市、加地块同理：

1. 在父条目正文里加上它的名字（挽歌堡的 `区位` 列表），让模型知道这个地方存在、会把它写进 `世界.地点`。
2. 写正文文件，放在父条目同目录，命名沿用 `势力-类别-城市-区位`。缩进和兄弟条目一致；想自成一段就用 `---` 开头并写完整顶层键。
3. 在 `worldbook/命定之诗.yaml` 里紧跟兄弟条目加配置：名称前缀 `[本体][势力][诺斯加德联盟][城镇][挽歌堡]`；绿灯；主关键词是本级名和别名；次关键词 `与任意` 填父级名；插入位置、顺序和兄弟一致；递归两项都是 `true`；不设黏性。
4. 地点要上地图或参与路线时，同步 `content/geography/places.yaml`（`parent` 指向上级，名字与世界书一致），见 [地理数据](geography.md)。
5. 新开一座城市时，给它和它的区位单独一个号段，确认不和同区块里别的城市共号。号不够时整体后移本区块后面的条目，不要和别的城市挤在同一个号上。

## 五、验证

- `pnpm card check`：确认新文件已接入 YAML，并且没有新增 `[挂靠]` 警告。
- 构建后用酒馆的提示词预览，至少看这几种：当前地点在该区位；只在父城市；路径里没有该城市但聊天里提到区位名；同一轮提到同势力的两座城市；离开后下一楼旧地点是否已经消失。重点看缩进子块挂在了谁下面。
- 静态检查只能证明字段和文件存在，模型是否真的按格式写出 `世界.地点`、提示词里拼出的 YAML 是否正确，要在酒馆里看过才算验证。
