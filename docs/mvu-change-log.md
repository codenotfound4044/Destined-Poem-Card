# MVU 变量修改日志

`[本体][变量]mvu变量修改日志` 是默认启用的 EJS 蓝灯条目，位于 `worldbook/命定之诗/变量/mvu变量修改日志.ejs`，需要 ST-Prompt-Template。它在提示词构建时只读消息楼层的 `stat_data`，比较当前有效状态与上一轮更新前状态，直接输出简略净变化；无需更新 FrontEnd 或 Automated-script，也不写入 chat/message 日志缓存。

`[本体][变量]variables` 当前变量展示也依赖已启用的「公共函数」条目，以及 ST-Prompt-Template 设置中的「启用 generate before/after 注入支持」。缺少 `destinyVisibleState` 时，展示条目会输出配置提示，不读取或展示未过滤的变量；请按提示启用条目和注入支持。

条目在 `worldbook/命定之诗.yaml` 中按指定深度 1、系统角色、顺序 99998 插入，位于 `[本体][变量]variables`（99996）和事件信号适配（99997）之后，不与后者占用同一顺序。

输出标签为 `<mvu变量上一轮次修改日志>`，说明文案为“上轮净变化已生效，勿重复执行；此处仅记录变动信息。”

- 数字只报净增减；文本只报更新、填写或清空；布尔只报最终值；字符串数组报新增/移除项。
- 对象整体新增或删除时短路，只报名称；已有对象按实际值类型递归比较，同一父对象的变动合并为一行，不重复描述、新闻或其他长文本。不维护 Schema 字段映射，新增字段和自定义结构自动覆盖；路径内部使用数组，名称含点号等特殊字符时用 JSON 引号括号表示，避免混淆层级。
- 自动化脚本或手动编辑已经写入楼层的结果包含在比较中；中间操作、失败请求、修改原因不属于快照 diff。
- 日志与当前变量展示共用 `destinyVisibleState(value)`：比较前对两份快照各自执行展示过滤，移除整个事件、隐藏物品/伙伴、离场未签约伙伴的私有字段和未解锁登神字段。过滤只操作深拷贝，不修改楼层变量。对象恢复可见时按新增处理，不展开初始化字段。
- 原始当前快照中仍存在、但已被当前展示规则剔除的节点，同时从旧比较基线剔除，避免把隐藏或离场误报成删除并泄露名称；真正删除的可见节点仍报告移除。
- `世界.时间` 保持字符串，严格按变量更新规则 `${某某}纪元${yyy}年-${mm}月-${dd}日-${星期}-${hh}:${mm}` 解析，例如 `复兴纪元488年-3月-15日-星期一-14:00`。星期必填，时分均为两位数字，采用24小时制；不兼容季节、命名月份、时段前缀或省略星期。检查年月日、闰年和时分范围；不核验星期与日期对应关系。合法的同纪元前后时间输出“推进/回退N天N小时N分钟”；仅格式不同则报告时点未变。纪元变更时只显示原时间 → 现时间，不计算差值。日历计算采用延伸公历，不模拟历史改历造成的日期跳空；使用 UTC 和 `setUTCFullYear()`，避免宿主时区及1–99年的偏移，不额外增加2000年。
- 当前时间解析失败时，即使值未改变也报告原值、错误原因，要求下一轮 MVU 修正 `/世界/时间`，不猜测剧情日期、不自动改值。旧基线无法解析但当前值合法时只报告无法计算时间差，不要求改写已修复的当前值。
- 所有楼层搜索共用最后20层消息的窗口，使用有界 `for` 循环，不向窗口外扩展。正常交替聊天相当于当前用户楼与前两楼比较；非交替聊天按有效状态和助手消息寻找基线。`regenerate` 的目标回复已经由宿主删除，因此与普通生成一样选择现存快照，不再额外跳过助手楼；`swipe`、`continue`、`append`、`appendFinal` 则排除仍在聊天中的目标助手楼及后续消息。缺少基线时不生成普通字段 diff，但仍解析当前时间；没有差异且时间合法时不输出。

## 其他条目复用时间解析

`worldbook/命定之诗/变量/公共函数.ejs` 集中注册 `destinyParseTime(value)` 和展示与日志共用的 `destinyVisibleState(value)`，后续公共函数也放在此处。蓝灯条目名称是 `[本体][变量]公共函数`，正文首行的 `@@generate_before` 让它在生成前执行，紧随其后的 `@@always_enabled` 保证 ST-Prompt-Template 的“反转特殊条目启用状态”设置不会把这个依赖条目排除；只注册函数，不输出提示词，也不读写游戏变量。使用日志或下列调用的条目时，需保持这个公共条目和 ST-Prompt-Template 的内容注入功能启用。该条目由公共依赖声明控制，不能再依赖世界书普通启用开关。

```ejs
<%_ {
  const time = destinyParseTime(getMessageVar('stat_data.世界.时间'));
  if (time.error) {
    // time.error 是可读的错误原因；由调用方决定如何处理。
  } else {
    // time.era 是纪元名称，time.minutes 是用于同纪元时间差计算的 UTC 分钟数。
  }
} _%>
```

返回值为 `{ era, minutes }` 或 `{ error }`；只有 `era` 相同时才比较 `minutes`。解析格式和错误信息只在公共文件里维护，日志条目不再保留自己的实现。其他条目直接调用同名函数，不复制函数体，也不要把函数存进 char/chat/message 变量。

公共函数通过 ST-Prompt-Template 的 `define()` 注册，使用普通 `function` 定义；`destiny` 前缀用于避免与其他角色卡的共享函数重名。它不依赖 EJS 文件 `include`，也不依赖日志条目是否启用。
