# 推送到酒馆

双击 `打开工作台.cmd`（或运行 `pnpm workbench` / `pnpm dev`）启动本机服务，默认地址为 `http://127.0.0.1:5173`。工作台的「推送到酒馆」页提供连接选择、目标检查、构建并覆盖同步、执行日志和备份恢复。

## 首次连接

1. 打开工作台的「推送到酒馆」页，下载连接脚本安装文件；也可复制页面提供的 `import` 代码。
2. 在目标酒馆的酒馆助手中单独导入为全局脚本并启用。连接脚本不打包进角色卡；只有启用后，该酒馆页面才参与连接。禁用脚本即可停止该页面连接。酒馆装了加速插件 cocktail-plus 时，改写角色卡后插件会重建角色列表缓存，期间列表接口返回空的占位列表，酒馆会误弹「当前角色已不再可用」并刷新页面；连接脚本启用期间会给酒馆的角色列表请求加一层有界重读来避开（只针对 `/api/characters/all`，最多 10 次），推送写完卡后也会先等列表重建好再刷新酒馆助手。
3. 保持酒馆页面打开，工作台会自动显示连接。同一酒馆开了多个标签页时自动选最新的；连接了多个不同酒馆时需手动选择，再选择目标角色与世界书名称。
4. 先点「先检查」，确认目标后点「推送到酒馆」。酒馆页面需要能访问本机资源地址，所以要在运行工作台的这台电脑上打开酒馆。

安装文件为 `/sync/install.json`，全局脚本入口为 `/sync/bridge.mjs`；导入地址以工作台当前显示的资源地址为准。

## 覆盖范围

推送把当前 local 构建（界面资源来源见下文）的角色卡资源（含开场白、脚本与正则）和指定世界书写入目标，保留聊天记录。头像换成构建 PNG 里的封面（`card/cover/cover.png`）：在写完卡数据之后调用酒馆的 `/api/characters/edit-avatar`，所以酒馆会把新卡数据重新写进新图。比对和读回校验都按解码后的像素进行，因为酒馆会重新编码 PNG；画面已经相同时不重复写。旧头像（去掉卡数据后的画面）会存进备份，回滚和备份恢复时一起还原。

卡名和世界书名默认取 `release.json` 派生的名字，比如 `命定之诗与黄昏之歌v4.3`。目标是按名称匹配的，推到别的名字的卡时要选择或填写目标；工作台会记住上次推送的目标。卡里自带的角色变量（地图标记、地图绘制、状态栏编辑开关、开局预设、资源版本）以工作区为准整体替换，玩家在酒馆里加的标记和画的线会被清掉；只在酒馆运行时产生、卡里没有的角色变量（如状态栏主题）保留。聊天变量不动，地理路线由加载脚本按版本更新。目标世界书名称可填写或选择；执行前核对目标，避免覆盖同名的其他用途世界书。

实际写入前保存备份，完成后提供结果、备份位置与日志。失败信息显示在工作台；写入失败会自动回滚，回滚不完整时用备份恢复。备份恢复用于撤回工具覆盖的资源，不是聊天或存档迁移。

## 界面资源从哪里加载

推送页「界面和脚本从哪里加载」有两个选项：

- **这台电脑（开发测试）**：默认。界面资源从本机 `pnpm dev` 加载，改完马上能看到；但只有在这台电脑上、工作台开着时才能正常显示，手机或别的设备上加载不出来。
- **已发布的程序资源（CDN）**：卡里的加载器从 CDN 读 `release.json` 里 `assets.version` 对应的资源，手机和别的设备也能用，CDN 连不上时会自动换下一个。只有资源版本已经用 `pnpm card assets verify` 标记发布后才能选。推送前先到 CDN 逐个入口核对，缺文件就停下，不写入酒馆。

要推给手机上玩的酒馆：只要这台电脑的浏览器能打开那个酒馆（云服务器，或用局域网地址访问的酒馆），在电脑上打开它、选 CDN 资源推送即可；卡写进酒馆服务器，手机刷新就能看到。资源版本和加载规则见 [程序资源版本](versioning.md#程序资源版本)。

命令行用 `pnpm card sync --assets cdn`；构建用 `pnpm card build --assets cdn`，产物仍在 `dist/local/`，`report.json` 的 `assetSource` 记录来源，推送时和本次选择不一致会要求重新构建。

## 命令行

```sh
pnpm card sync status
pnpm card sync --dry-run
pnpm card sync
pnpm card sync --character "目标角色" --worldbook "目标世界书" --client "连接编号"
pnpm card sync --no-build
pnpm card sync restore <backupPath>
```

`sync` 默认构建 local profile；`--dry-run` 执行构建与目标检查而不写入酒馆。`--no-build` 使用现有本地产物，仅在已确认产物对应当前源码时使用。连接编号可从 `status` 查看；多个连接时指定目标。恢复使用同步结果中的备份路径。

## 验证情况

推送、读回校验、备份恢复已在本地隔离酒馆（SillyTavern 1.19.0、酒馆助手 4.11.3）用命令行和工作台各实测一次。推送成功后，仍需在酒馆内检查开场白、页面加载、脚本触发、世界书与变量读写；模型真实生成另行验证。
